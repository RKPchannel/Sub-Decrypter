# Sub-Decrypter

Однофайловая утилита для Windows, Linux и Android/Termux, которая превращает
«клиентские ключи» VPN-приложений в обычные ссылки-подписки и извлекает из них
готовые конфиги.

Механика:

```
ключ клиента → ссылка-подписка → конфиги → <домен>.txt
```

---

## Что умеет

### 1. Расшифровка ключей

Поддерживаются:

- `happ://crypt/…`
- `happ://crypt2/…`, `happ://crypt3/…`, `happ://crypt4/…`
- `happ://crypt5/…`
- `incy://crypt1/…` и другие `incy://cryptN/…`
- `v2raytun://import/…`

Особенности:

- ключи RSA/AES **встроены прямо в `.py`-файл** (сжаты `zlib` + `base64`), внешние
  JSON-файлы не нужны;
- поддерживаются вложенные ключи (ключ внутри ключа), URL-кодировка,
  невидимые символы Telegram и лишняя пунктуация вокруг ссылки;
- для `crypt1–4` перебирается несколько видов RSA padding;
- для `crypt5` используется маркер из payload, перебор ключей, salted/unsalted
  варианты и AEAD (ChaCha20-Poly1305 / AES-GCM);
- для `incy` ключ выводится из keymat по смещениям и соль-частям, с проверкой
  отпечатка `key_fingerprint`.

Если встроенные ключи устареют, рядом со скриптом можно положить свежие файлы
в папку `keys/`. Файлы из `keys/` имеют приоритет над встроенными.

### 2. Загрузка подписок как у приложения

- заголовки `X-HWID`, `X-Device-Model`, `X-Ver-OS`, `X-App-Version`;
- добавление `?hwid=…` к ссылке;
- свой HWID или сгенерированный при первом запуске;
- ручная обработка `301/302/303/307/308`, включая редиректы на не-HTTP-схемы;
- браузерный User-Agent как запасной вариант при `403/418/500/503`;
- ожидание при `429` с учётом `Retry-After`;
- повторы при обрыве соединения.

### 3. Разворот любых редиректов и обёрток

Поддерживаются переходы на:

- `http(s) → http(s)`;
- `http(s) → happ://add/…`;
- `incy://import/…`, `streisand://import/…`, `hiddify://import/…`;
- `clash://install-config?url=…`, `v2box://install-sub?url=…`;
- `sub://<base64>`;
- сразу на ключ `happ://crypt…`, `incy://…`, `v2raytun://…`.

HTML-страницы-редиректоры разбираются через:

- `<meta http-equiv="refresh" content="0; url=…">`;
- `location.href = "…"`, `location.replace("…")`;
- `atob("…")`;
- `href` с подсказками (`/sub`, `token=`, `.txt`, raw GitHub и т.п.).

### 4. Извлечение конфигов

Из ответа вытаскивается всё, что похоже на конфиг:

- `vless://`, `vmess://`, `trojan://`, `ss://`, `shadowsocks://`,
  `hysteria2://`, `hy2://`, `tuic://`, `socks5://`, `socks4://`;
- Base64 любой вложенности;
- URL-encoded строки;
- JSON Xray/V2Ray, sing-box, Clash JSON;
- YAML Clash (с PyYAML точнее, но встроенный разбор тоже работает);
- HTML-страницы;
- склеенные конфиги вида `vmess://…,vless://…`;
- комментарии после `#` сохраняются целиком в начале строки.

### 5. Результат

Конфиги пишутся в файлы `<домен>.txt` **рядом со скриптом**, без внутренних
папок устройства. Повторный запуск дописывает только новые конфиги. В настройках
можно включить перезапись файла.

## Требования

- Python **3.8+**.
- `cryptography` — нужна только для расшифровки `crypt`/`incy`.
- `PyYAML` — **необязательна**; если установлена, YAML Clash разбирается точнее.
- Windows, Linux, Android/Termux — используются только `os.path`, `urllib` и SSL
  из стандартной библиотеки.

Установка зависимостей:

```bash
# Windows / Linux
pip install cryptography
pip install pyyaml

# Termux
pkg install python
pip install cryptography
pip install pyyaml
```

Без `cryptography` продолжают работать `v2raytun`, загрузка подписок и
извлечение конфигов; `crypt`/`incy` будут недоступны.

## Как пользоваться

Скрипт не требует установки — просто положите `Sub-Decrypter.py` в любую
папку и запустите.

### Меню

```bash
python Sub-Decrypter.py
```

Пункты меню:

1. обработать одну ссылку/ключ;
2. пакетный режим из файла;
3. вставить несколько ссылок/ключей по одной;
4. устройство / X-HWID;
5. настройки;
6. информация;
0. выход.

### Одна ссылка или ключ

```bash
python Sub-Decrypter.py "happ://crypt/..."
python Sub-Decrypter.py "incy://crypt1/..."
python Sub-Decrypter.py "v2raytun://import/..."
python Sub-Decrypter.py "https://example.com/sub?token=..."
```

Флаг `--no-menu` отключает меню после обработки:

```bash
python Sub-Decrypter.py "ключ" --no-menu
```

### Пакетный режим

Файл `links.txt` — по одной ссылке/ключу на строку, `#` в начале строки — комментарий:

```text
# мои подписки
happ://crypt/AAAA...
incy://crypt1/BBBB...
https://example.com/sub/token=...
v2raytun://import/CCCC...
```

Запуск:

```bash
python Sub-Decrypter.py -b links.txt
```

### Первый запуск

При первом запуске создаётся `device.json` рядом со скриптом. Если запуск
интерактивный — предлагается ввести свой HWID или сгенерировать устройство.
В неинтерактивном режиме (например, с `-b`) устройство генерируется автоматически.

Позже HWID можно поменять в меню «устройство / X-HWID».

## Файлы рядом со скриптом

| Файл | Назначение |
|---|---|
| `Sub-Decrypter.py` | сам скрипт |
| `device.json` | HWID, модель, версия ОС и Happ |
| `settings.json` | настройки из меню (создаётся при сохранении) |
| `<домен>.txt` | итоговые конфиги |
| `keys/*.json` | необязательные свежие ключи вместо встроенных |

Рекомендуется не коммитить `device.json`, `settings.json`, `*.txt` и `keys/`.

## Что внутри кода

Условная структура одного файла:

1. **Настройки и устройство** — значения по умолчанию, загрузка/сохранение
   `settings.json` и `device.json`, генерация правдоподобного Android-устройства.
2. **Встроенные ключи и крипта** — `EMBEDDED_KEYS`, функции `decrypt_happ`,
   `decrypt_crypt5`, `decrypt_incy`, `unwrap_v2raytun`, `resolve_key`.
3. **Загрузчик** — `urllib.request` с ручными редиректами, заголовками устройства
   и браузерным fallback.
4. **Парсеры конфигов** — `find_configs`, `json_to_links`, `singbox_to_links`,
   `clash_to_links`, `extract_from_content`.
5. **Конвейер** — `process_target` разворачивает ключи/обёртки/редиректы,
   `save_configs` пишет результат в `<домен>.txt`.
6. **Меню и CLI** — `main_menu`, `settings_menu`, `device_menu`, `main`.

Зависимости сведены к минимуму: стандартная библиотека + `cryptography`;
`PyYAML` используется только если установлен.
